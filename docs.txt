# Valorant 自動録画ソフトウェア 要件定義書

## 1. プロジェクト概要
既存の録画ソフトにおける「録画が開始されない」「動作が重い」といった課題を解消し、ゲームパフォーマンスに影響を与えない軽量で確実なValorant専用の自動録画・リプレイアプリケーションを開発する。長期間の運用に耐えうるストレージ管理や、ゲーマー向けの高度な音声管理・クリップ機能も備える。

## 2. コア機能要件 (録画・自動化)
### 2.1. アプリケーションのライフサイクル管理
- Valorantのプロセス起動を常駐またはタスクスケジューラ等で検知し、本アプリケーションを自動起動する。
- Valorantのプロセス終了に合わせて、本アプリケーションも待機状態または終了状態に移行する。

### 2.2. 自動録画制御
- 試合開始（エージェント選択後、ローディング画面完了時など）を正確に検知し、録画を自動開始する。
- 試合終了（リザルト画面移行時など）を検知し、録画を自動停止・ファイル保存する。
- 録画失敗を防ぐためのリトライ機構、またはプロセス監視による確実な状態同期を実装する。

### 2.3. イベント検知とチェックポイント記録
試合中の以下のイベントを検知し、録画ファイルのタイムスタンプと紐づけてメタデータ（JSON等）として記録する。
- ラウンド開始 / ラウンド終了
- キル / デス / アシスト
- 試合全体の勝敗結果（勝利・敗北・引き分け）
- 試合全体の最終スコア（例: 13-10）
- ラウンドごとの勝利理由（敵殲滅、スパイク設置/解除、タイムアップ等）
- 使用エージェント
- プレイヤー個人の最終KDA（キル/デス/アシスト）

### 2.4. 音声・録画設定のカスタマイズ
- 解像度・FPS・ビットレート設定（1080p/1440p、60fps/120fpsなど）の柔軟な変更。
- エンコーダの明示的選択（NVIDIA NVENC / AMD AMF / Intel QSV）。
- マイク音声の分離（マルチトラック録音）: 「システム音（ゲーム音含む）」と「自分のマイク音」を別々の音声トラックとして録音し、リプレイや編集時に個別にミュート・音量調整を可能にする。

### 2.5. ストレージ管理機能（容量パンク防止）
- 自動削除（オートクリーンアップ）: 保存容量の上限（例: 50GB）または保存期間（例: 30日）を設定し、超過分は古い録画から自動的に削除する。
- お気に入り（保護）機能: 神プレイなどの重要な録画を自動削除対象から除外するためのロック機能。

### 2.6. フェイルセーフと通知機能
- 録画開始時や保存完了時に、控えめなデスクトップ通知（またはシステムトレイのアイコン変化）で状態を可視化し、録画漏れの不安を解消する。
- 録画開始前にストレージの空き容量をチェックし、不足している場合は警告を通知する。

## 3. リプレイ機能要件 (UI・プレイヤー)
### 3.1. 録画一覧画面
- 録画された試合のリストをサムネイル付きのグリッド（2列以上）で一覧表示する。サムネイルをクリックすることで動画を再生する。
- 各リストアイテムには、日付、マップ、勝敗、スコア、KDA、使用エージェントなどの基本情報を表示する（Riot API等の連携による自動取得）。
- お気に入り（保護）状態のアイコン表示と切り替えトグル。

### 3.2. 動画プレイヤー画面
- カスタムシークバー（再生バー）の実装。
- 記録されたチェックポイント（キル、ラウンド開始等）をシークバー上にアイコンやピンとして視覚的に表示する。
- チェックポイント表示のフィルタリング機能（例：「キルのみ表示」「ラウンド開始・終了を非表示」などのON/OFF設定）。
- 再生速度の変更機能（例: 0.5x, 1.0x, 1.5x, 2.0x）。
- 5秒スキップ機能（前へ5秒戻る / 次へ5秒進む）。
- 再生エラー発生時のエラーログ表示機能（トラブルシューティング用）。

### 3.3. クリップ（ハイライト切り出し）機能
- リプレイ画面で任意のチェックポイント（キルやクラッチなど）を選択し、「その前15秒・後5秒」などを別ファイルとして切り出してエクスポートする機能。
- SNS共有を容易にするため、再エンコードなし（無劣化かつ高速）での切り出し処理を実装する。

## 4. 非機能要件
### 4.1. パフォーマンス（軽量化）
- ゲームプレイ（FPSやPing）への影響を極限までゼロに近づける。
- 録画エンジンとしてFFmpegを採用し、ハードウェアエンコーダ（NVENC等）とDesktop Duplication API (ddagrab) を使用してCPU負荷を最小限に抑える。画面全体の録画となるため、録画対象のディスプレイはユーザーが選択可能とする。
- UI描画やバックグラウンド処理がゲームの割り込み処理を阻害しないアーキテクチャを採用する。

### 4.2. 安定性・堅牢性
- Riot Vanguard（アンチチートシステム）に誤検知されない安全な方法でゲーム内イベントを取得する。
- 録画中にクラッシュした場合でも、それまでの録画データが破損しないフォーマット（MKV等）を採用する。

## 5. 技術的検討事項 (開発フェーズ向けメモ)
- イベント取得方法: 画面キャプチャによる画像認識(OCR)は負荷が高いため、Valorantがローカルに出力するログファイル（ShooterGame.log等）の監視、またはRiot公式/ローカルAPI（Client API）の活用を第一候補とする。
- 録画エンジン: FFmpegをサブプロセスとして呼び出し、軽量かつ安定した録画を実現する。
- 音声分離: FFmpegのWASAPI入力を使用し、システム音とマイク音を別トラックとして記録する。
- クリップ機能: メタデータ（JSON）のタイムスタンプを元に、FFmpegのストリームコピー（`-c copy`）を利用して高速に切り出す手法を採用する。
- UIフレームワーク: 軽量化を重視し、PyQt6を採用してクロスプラットフォームに対応したUIを構築する。
